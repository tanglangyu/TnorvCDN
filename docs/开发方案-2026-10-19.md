# TnorvCDN 系统性完善开发方案（2026-10-19）

依据：5 路代码侦察（套餐/下发管线/双端页面盘点/节点字段消费）。全部行号引用见侦察记录。

## 一、现状核心事实

1. **下发**：所有变更 → `publishQueue.Enqueue(cluster)` → Worker ≤500ms 内 `PublishAsync`（仅 bump `Cluster.ConfigVersion`，成本低）→ 节点 10s 轮询 `/grpc/config` 比对版本后拉全量。即当前所有变更实际上 **~10.5s 内生效**，无任何"默认不实时"机制；gRPC 路径还总是 `changed=true` 全量重建（浪费）。
2. **配额**：Plan 仅 MaxServers/MaxDomains/MonthlyTrafficMB 三项；前两项只在创建站点时检查（PUT 更新不复查）；功能开关只有 `User.Features`（fail-open，仅 5 个键被检查，无任何 UI）。
3. **套餐管理**：无升级/降级/退订/自动续费；不同套餐购买会并行叠加订阅；订阅无 PUT；到期不停站（仅创建时校验）；UsageRecord 无写入方（账单数据源缺失）；多处前端 bug（plans_list 流量字段覆盖、订阅页死列、邀请码 DELETE 缺 /admin 前缀）。
4. **页面**：管理端 77 路由中 ~40% 纯只读（其中不少"页名与内容不符"：内容封禁页只是站点表、日志策略页只有统计、解析测试页无输入…），24 个已写好但未注册路由的死视图；用户端 15 个只读页，高防购买/消息已读/优惠券兑换/证书上传等入口缺失。
5. **死字段**（双端可配但节点不消费）：Advanced.Compression / Websocket / MaxBodySizeMB / Mp4Drag；Security.DeniedCountries/Provinces（Cidrs 主控无填充）；CacheRule.ClientTtlSeconds；location 级 Rewrites/请求头/Cc；节点 CacheDir/MemoryCacheMB。

## 二、设计决策

### D1 下发策略（默认批量 + 站点级实时）
- `Servers.RealtimePublish bool`（默认 false，**仅管理员可改**）。
- 队列改造：`EnqueueImmediate(cluster)`（原语义）与 `EnqueueDeferred(cluster)`；Worker 即时队列照旧（≤500ms），延迟集合按 `Publish:DeferredIntervalSeconds`（默认 300s）周期性批量发布脏集群。
- 语义：**管理端/节点回调（证书签发、ACME 挑战）/NS DNS 记录变更 = 即时**（运营与解析关键路径）；**用户端配置变更 = 默认延迟批**；站点开了实时则即时。管理端站点列表提供行内"实时下发"开关与"立即下发"按钮（`POST /admin/servers/{id}/publish`），用户端展示但不可改。
- 兜底：Worker 启动时 `EnqueueAll`（修复内存队列重启丢失）；HTTP/gRPC 统一版本比对（gRPC 不再每次全量）；`TrafficBlockedAsync` 的 AccessLogs 聚合结果缓存 60s（每次发布/每次拉取都算一遍是最大热点）。

### D2 功能配额矩阵（套餐级开关）
- `Plan.Features`（JSON）：`{"cache":true,"waf":true,"cc":true,"jsShield":false,"urlAuth":true,"referers":true,"edgeScripts":false,"aiGuard":false,"basicAuth":true,"customPages":true,"webp":false,"websocket":true,"grpc":false,"compression":true,"https":true,"locations":true,"ns":true,"lb":false,"antiDdos":true,"api":true,"tickets":true,"finance":true,"maxLocations":10,"maxCerts":5}`；空=全开（向后兼容）。
- 统一校验服务 `PlanGate.CheckAsync(db, uid, featureKey)`：管理员放行；合并 **User.Features**（管理员对单用户强制关，优先）与 **Plan.Features**（套餐未含→拒）；fail-closed（仅对"明确 false"拒绝，其余放行，保持现有 fail-open 兼容）。
- 接线：advanced（customPages/webp/websocket/grpc/basicAuth/edgeScripts）、security（waf/cc/jsShield/urlAuth/referers/aiGuard）、cache、ssl(https)、locations、lb、ns（替换现有 FeatureEnabledAsync）。拒绝返回 403"当前套餐未包含「XX」，请升级套餐"。
- `GET /user/my-plan` 返回 `features` + `quotas`（供前端禁用 UI）。

### D3 套餐闭环
- 订阅加 `AutoRenew`（默认 false）；升级 `POST /user/subscriptions/upgrade`（差价 = (新-旧)月价 × 剩余天数/30，正差价余额扣款、负差价按比例延长到期日）；退订 = AutoRenew=false（到期自然失效）。
- Billing 扩展：到期未续费（且非豁免）→ 停用站点；AutoRenew 且余额足够 → 自动续费。订阅 PUT（管理员续期/改套餐/停用）。
- UsageRecord：在 Billing 每小时巡检时按用户 MERGE 当月用量（修复账单零数据）。

### D4 页面修复（分期）
- P3 管理端：IP 库接 /admin/iplib、CC 解封指令通道、ns_routes 接节点线路编辑、ns_domains 补编辑、ns_test 解析测试表单、nodes 节点增删、日志保留策略、删除死视图与重复页、修 DELETE 前缀 bug。
- P4 用户端：高防购买/绑定、消息已读/删除、优惠券兑换、证书上传、WAF 日志导出+快捷加黑、流量图表化、ns 套餐购买入口。
- P5 死字段治理：节点消费 compression/websocket/maxBodySize、location 级 rewrites/请求头、CacheRule.ClientTtl、location CC 独立限流器。

## 三、分期与验收

| 期 | 内容 | 验收 |
|---|---|---|
| P1（本轮） | D1 全部 + D2 模型/服务/接线 + 管理端开关 UI + 套餐功能矩阵编辑 | 用户改配置默认 5 分钟批生效；实时站点 ~10s；未购功能 PUT 403 |
| P2 | D3 套餐闭环 + 双端套餐页修复 | 升级/退订/自动续费/到期停站可用 |
| P3 | 管理端只读页接线 | 上表清单逐页可操作 |
| P4 | 用户端功能补齐 | 同上 |
| P5 | 死字段生效 + 性能收尾 | 关压缩真不压、WS 开关生效、413 生效 |

性能红线：发布只 bump 版本（保持）；节点拉取命中版本即返回（含 gRPC）；AccessLogs 聚合缓存化；延迟发布把用户侧高频保存合并为 ≤1 次/5min/集群。
